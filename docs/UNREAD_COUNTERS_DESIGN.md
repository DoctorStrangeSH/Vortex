# Серверные счётчики непрочитанных — проект реализации

**Статус: модель и тесты готовы; функции, миграция и правила ещё НЕ развёрнуты.**

Сейчас сообщения содержат `senderId` и `readBy[]`. Клиент отмечает только реально видимые сообщения. Источником истины остаётся каждый документ сообщения; хранить «точный» счётчик на клиенте или вычислять его из последних 50–100 сообщений нельзя.

## Предлагаемая проекция

- Данные: приватный для пользователя документ `users/{uid}/unreadChats/{chatId}` с `count`, `updatedAt` и версией схемы.
- Клиент подписывается только на **свои** документы и отображает счётчики рядом с чатами. Внешнему пользователю читать/изменять чужие счётчики запрещено.
- Доверенный серверный обработчик реагирует на создание, изменение `readBy` и удаление сообщения. Чистая функция `server/unreadCounterModel.js` вычисляет изменение числа непрочитанных для участников (кроме отправителя).
- `server/unreadEventProjector.js` задаёт проверенную тестами транзакционную последовательность: сначала проверка event ID в журнале, затем чтение всех затронутых счётчиков, запись дельт и квитанции события **одной атомарной транзакцией**. Реальный Firebase-адаптер ещё не создан.
- События могут приходить не по порядку. Промежуточное внутреннее значение может оказаться отрицательным, если удаление обработано раньше создания; **нельзя обрезать его до нуля в каждой транзакции**, иначе конечный результат станет ошибочным. UI отображает не меньше нуля, а сервер после завершения миграции проверяет итог и пересчитывает расхождения по полной истории.

## Обязательные проверки перед включением

1. Установить редакцию Firestore и проверить выбранный Firebase-проект под авторизованной сессией. В рабочей среде сейчас `firebase firestore:databases:list` возвращает **Failed to authenticate**.
2. Провести аудит Firestore Rules и дать чтение собственных проекций, запретив клиентские записи; проверку правил прогнать в Emulator Suite.
3. Запустить доверенный обработчик в тестовом проекте; проверить повторную и неупорядоченную доставку событий, конкурентные отметки, удаления и участника, покинувшего группу.
4. Выполнить серверный backfill для существующих сообщений с учётом `readBy`. Во время миграции скрыть неполные счётчики, переключаться на новый UI только после проверки итогов.
5. Проверить затраты и доступность облачных обработчиков для выбранного тарифного плана **до** развёртывания. Без разрешения владельца не включать платные сервисы.
6. Smoke-test двух аккаунтов/двух устройств: чтение на одном устройстве, мгновенное обновление другого; не считать просмотром невидимые сообщения.

`getUnreadCounterDeltas` и `projectUnreadEvent` — расчёт и транзакционная схема с тестовым адаптером, **не** готовая облачная функция. Реальная запись в Firebase, журнал обработанных событий, права доступа и визуальные бейджи будут отдельным этапом после проверки окружения.
