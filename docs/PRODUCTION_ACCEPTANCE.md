# Vortex 1.0 — production acceptance

**Статус:** подготовлено; ручная проверка владельцем и коллегами не подтверждена.  
**Режим:** текущий Production Firebase `vortex-messenger-4ea97`.  
**Важно:** этот план не разрешает рискованные миграции, изменение Production Rules или массовые операции с данными.

## Правила безопасного тестирования

- Тестировать только с коллегами, которые согласились участвовать.
- Для проверки создавать отдельный временный тестовый личный чат или группу; не использовать рабочие переписки и реальные вложения с персональными данными.
- Не просить коллег отправлять пароли, коды входа, токены, документы или чувствительные данные.
- Не удалять аккаунты, существующие чаты, историю, участников или сообщения ради теста.
- Не менять Firebase Rules, Authentication providers, тариф, Storage или настройки проекта в рамках ручной приёмки.
- Если тест выявил проблему с доступом, приватностью или потерей данных — остановить сценарий и зафиксировать шаги; не пытаться исправлять Production вручную.
- Для каждого результата записывать дату, версию приложения/commit, браузер, роль тестировщика и ожидаемое/фактическое поведение. Не записывать персональные данные.

## Обязательные ограничения

- Не считать отсутствие ошибки в UI доказательством успешной записи: сверять результат у обоих участников.
- Не считать успешный Production smoke test доказательством корректности всех Security Rules или приватности legacy-данных.
- Не выполнять проверки чтения чужих приватных документов через реальные аккаунты. Такие негативные проверки остаются в Firebase Emulator.
- Не включать Storage для теста вложений. Проверять только уже доступный и документированный путь, не отправляя чувствительные файлы.
- Не тестировать удаление аккаунта, каскадное удаление данных, миграции и изменение правил на живых данных.

## Дефекты и эскалация

Для дефекта фиксировать ID сценария, commit/build, браузер/устройство, точные шаги, ожидаемое и фактическое поведение, время события и безопасный скриншот без личных данных.

Любая потеря/дублирование сообщений, утечка приватных данных, неверное членство или неожиданный доступ — блокирующий дефект. Прекратить соответствующий сценарий, сохранить безопасные диагностические сведения и исправлять через отдельную ветку с CI/Emulator до публикации.

## Gate Vortex 1.0

Production acceptance считается завершённой только после подтверждения применимых сценариев владельцем и коллегами, устранения блокирующих дефектов, успешного CI на финальном commit и повторной проверки исправленных сценариев.

Staging-проект отложен по решению владельца. Его отсутствие не скрывается: Production smoke/acceptance проверяет реальный пользовательский поток, но не заменяет изолированную проверку миграций, Rules rollout и destructive operations. Такие операции остаются вне релизного процесса 1.0 без отдельного безопасного плана.

Все статусы NOT RUN до фактического подтверждения.
