# Vortex Messenger 🌪️

Веб-мессенджер на **Preact + Vite + Firebase Authentication/Firestore**. Проект на ранней стадии разработки и пока не предназначен для чувствительной переписки.

## Разработка

```bash
npm ci
npm run dev
npm test
npm run build
```

Публичный Firebase API key в `src/services/firebase.js` не является серверным секретом: доступ к данным должны ограничивать серверные правила Firestore и Storage.

## Важные ограничения безопасности

- **Обычные сообщения не шифруются end-to-end.** Наличие `encryptionService.js` не означает, что он защищает обычную переписку. Нужен проверенный протокол, управление ключами и проверка устройств.
- **Двухфакторная аутентификация не реализована.** `twoFactorService.js` содержит демонстрационный локальный код, не защищающий Firebase Authentication.
- **Правила Firestore и Storage необходимо проверить и развернуть отдельно.** В репозитории пока нет проверенной серверной политики доступа; защита только на клиенте недостаточна.
- Вложения пока сохраняются как data URL в документ Firestore: временный лимит 350 КБ. Для больших файлов нужен Firebase Storage с правилами и квотами.
- Подписка чата получает последние 100 сообщений; полноценная загрузка старой истории потребует пагинации.

## Дорожная карта

1. **P0 — Безопасность:** проверить реальные Firestore rules, разграничить доступ участников чатов, запретить подмену авторства/чужое редактирование, реализовать проверяемую MFA.
2. **P0 — Надёжность:** стабильные ID личных чатов, атомарная отправка и превью, пагинация, офлайн-синхронизация.
3. **P1 — Медиа:** Firebase Storage, превью, ограничение размера и стоимости хранения.
4. **P1 — Приватность:** модель угроз, независимый аудит E2EE, управление ключами устройств.
5. **P1 — Продукт:** удобные группы и каналы, поиск, адаптивный интерфейс, уведомления, доступность.
6. **Постоянно:** unit/integration/e2e-тесты, Firebase Emulator, CI, мониторинг и план восстановления.

Никогда не публикуйте service-account JSON или другие серверные секреты в клиенте.
